# Установка и запуск

## Требования
* Docker Engine 24+ и Docker Compose v2 (рекомендуется), **или** Node.js 22 и PostgreSQL 16.
* Сервер: 2 vCPU, 4 ГБ ОЗУ, 20 ГБ диска — достаточно для ~2000 сотрудников.

## Установка через Docker Compose

1. Скопируйте пример конфигурации и задайте секреты (не храните `.env` в репозитории):
   ```bash
   cp .env.example .env
   openssl rand -base64 48   # повторите для JWT_ACCESS_SECRET и JWT_REFRESH_SECRET
   ```
   Обязательно: `POSTGRES_PASSWORD`, `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` (не короче 32 символов),
   `PUBLIC_URL` — адрес, по которому пользователи открывают систему.
2. Запуск:
   ```bash
   docker compose up -d --build
   docker compose logs -f backend    # «Применение миграций…», затем «API: …»
   ```
   При каждом старте backend применяет миграции (`prisma migrate deploy`) и базовые справочники
   (роли, разрешения, правила уведомлений, шаблоны-примеры). Тестовые данные **не** загружаются.
3. Откройте `http://<сервер>:8080` (по умолчанию порт опубликован только на 127.0.0.1 — см. `HTTP_BIND`).

## Создание первого администратора

```bash
docker compose exec backend node dist/scripts/create-admin.js --login admin --name "Иванов Иван Иванович"
```
Пароль запрашивается интерактивно (не менее 10 символов, буквы и цифры). Для автоматизации можно передать
переменную окружения: `docker compose exec -e ADMIN_PASSWORD=... backend node dist/scripts/create-admin.js`
(пароль не передаётся аргументом командной строки, чтобы не попасть в историю оболочки).

Без Docker: `cd backend && npm run create-admin -- --login admin --name "..."`.

## Первичная настройка (администратор и специалист ОТ)

1. **Пользователи и настройки → Параметры**: наименование организации, горизонт «предстоящих» мероприятий и т.д.
2. **Справочники → Подразделения, Должности** (или импорт сотрудников с созданием отсутствующих значений).
   Для должностей укажите категорию работ, если от неё зависят правила.
3. **Справочники → Виды инструктажей / проверок, Правила** — по применимым нормативным и локальным документам
   (см. [REGULATORY.md](REGULATORY.md)). Без правил система не считает сроки и не показывает просрочки по ним.
4. **Справочники → Документы и инструкции, Комиссии.**
5. **СИЗ → Справочник СИЗ, Нормы выдачи** (вручную или загрузкой из Excel по шаблону).
6. **Справочники → Шаблоны печатных форм**: приведите формы к утверждённым и отметьте как проверенные.
7. **Пользователи**: создайте учётные записи, назначьте роли и зоны доступа; свяжите с сотрудником,
   если пользователь назначается ответственным за мероприятия.
8. **Сотрудники → Импорт из Excel**: скачайте шаблон, заполните, проверьте предпросмотр, загрузите.

## Запуск без Docker (production)

```bash
cd backend && npm ci && npx prisma generate && npx nest build
DATABASE_URL=... npx prisma migrate deploy && node dist/prisma/seed-base.js
NODE_ENV=production node dist/src/main.js           # за обратным прокси с HTTPS
cd ../frontend && npm ci && npm run build            # раздайте frontend/dist веб-сервером, /api проксируйте на backend
```
Пример конфигурации nginx — `frontend/nginx.conf`.
