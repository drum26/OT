# Эксплуатация

## HTTPS

**Вариант A — встроенный Caddy (Let's Encrypt).** Нужны DNS-имя, указывающее на сервер, и открытые порты 80/443.
```bash
# в .env:
DOMAIN=ot.example.by
PUBLIC_URL=https://ot.example.by
COOKIE_SECURE=true
docker compose --profile https up -d
```
Caddy получает и продлевает сертификат автоматически, добавляет HSTS. Порт `HTTP_PORT` оставьте опубликованным
только на `127.0.0.1` (по умолчанию).

**Вариант B — корпоративный сертификат / существующий обратный прокси.** Проксируйте HTTPS на
`127.0.0.1:${HTTP_PORT}` (контейнер `frontend`), передавайте `X-Forwarded-For`/`X-Forwarded-Proto`,
установите `COOKIE_SECURE=true` и `PUBLIC_URL=https://…`. Для внутреннего Caddy с собственным сертификатом
замените в `deploy/Caddyfile` строку сайта на `tls /path/cert.pem /path/key.pem`.

В production `COOKIE_SECURE=true` обязателен: refresh-токен хранится в cookie `HttpOnly; Secure; SameSite=Strict`.

## Резервное копирование

* **Автоматически**: сервис `backup` ежедневно в `BACKUP_HOUR` создаёт `pg_dump` (формат custom) в томе `backups`,
  копии старше `BACKUP_KEEP_DAYS` удаляются.
* **Из интерфейса**: «Пользователи и настройки → Резервное копирование» (создание и скачивание).
* **Вручную**: `./scripts/backup.sh ./backups`.
* Вложения хранятся в томе `uploads` — включите его в файловое резервное копирование, например:
  `docker run --rm -v ot_uploads:/d -v $PWD:/b alpine tar czf /b/uploads-$(date +%F).tgz -C /d .`
* Храните копии **вне сервера** (сетевое хранилище) и регулярно проверяйте восстановление на тестовом стенде.

## Восстановление из резервной копии

```bash
./scripts/restore.sh backups/ot-2026-10-01T02-00-00-auto.dump
```
Скрипт запрашивает подтверждение (`ВОССТАНОВИТЬ`), останавливает backend, выполняет
`pg_restore --clean --if-exists`, запускает backend (недостающие миграции применяются автоматически).
**Операция необратимо заменяет текущие данные** — перед восстановлением сделайте копию текущего состояния.
Вложения восстанавливаются распаковкой архива в том `uploads`.

Порядок проверен на тестовом стенде: копия → изменение данных → восстановление → изменение отменено,
учётные записи и вход сохранены.

## Обновление системы

```bash
./scripts/backup.sh ./backups          # 1. резервная копия
git pull                               # 2. новая версия
docker compose up -d --build           # 3. сборка; миграции применяются при старте backend
docker compose logs -f backend         # 4. контроль
```
Миграции только добавляются (`prisma migrate deploy`); откат — восстановлением резервной копии и предыдущей версией кода.

## Безопасность

| Требование | Реализация |
|---|---|
| Хранение паролей | argon2id; политика: ≥ 10 символов, буквы и цифры; смена временного пароля при первом входе |
| Авторизация | access-JWT (15 мин) в памяти браузера; refresh — httpOnly cookie, ротация, отзыв цепочки при повторном использовании |
| Перебор паролей | блокировка учётной записи после `LOGIN_MAX_ATTEMPTS` ошибок на `LOGIN_LOCK_MINUTES`; ограничение частоты `/auth/login` (10/мин с IP) |
| Права | проверка разрешений и зоны подразделений на сервере для каждого запроса |
| SQL-инъекции | Prisma (параметризованные запросы); сырые запросы — только шаблонные литералы без конкатенации |
| Валидация | class-validator, белый список полей (`forbidNonWhitelisted`), форматы дат/табельных номеров |
| CSRF | API принимает Bearer-токен (не cookie); cookie-эндпоинты refresh/logout требуют заголовок `X-Requested-With` и `SameSite=Strict` |
| XSS | React-экранирование, CSP без inline-скриптов, шаблоны печати с обязательным экранированием (`{{{ }}}` и скрипты запрещены) |
| Загрузка файлов | белый список расширений, проверка сигнатуры содержимого, лимит `UPLOAD_MAX_MB`, случайные имена, хранение вне веб-корня, `nosniff`, выдача только как вложение |
| CSV/Excel-инъекции | значения, начинающиеся с `= + - @`, экранируются при экспорте |
| Журнал | все изменяющие операции и входы — в `audit_logs`; пароли и токены маскируются |
| Секреты | только переменные окружения; в production приложение не стартует со слабыми JWT-секретами |
| Сеть | БД не публикуется наружу; frontend по умолчанию слушает 127.0.0.1 |

### Персональные данные
Хранятся только необходимые поля (ФИО, табельный номер, подразделение, должность, даты; телефон и e-mail — необязательны).
Срок хранения данных уволенных определяется организацией по применимым требованиям и фиксируется в настройке
`personalData.retentionYears`. Автоматическое удаление **не выполняется**: записи имеют контрольное значение,
решение об уничтожении принимает ответственное лицо (см. [STATUS.md](STATUS.md)).

## Мониторинг
* `GET /api/health` — проверка доступности API и БД (используется в healthcheck контейнера).
* Логи: `docker compose logs backend|frontend|backup`.
* Ошибки доставки уведомлений: «Пользователи и настройки → Настройки и уведомления».
