## Не реализовано / ограничения (явно)
* **Отправка e-mail и других внешних каналов** — архитектура каналов есть (`notifications/channels.ts`),
  но реальная отправка не реализована: при выборе канала EMAIL доставки получают статус `SKIPPED` («канал не настроен»).
* **Восстановление из интерфейса** намеренно не реализовано — только скриптом `scripts/restore.sh` администратором сервера.
* **Автоматическое удаление персональных данных** по истечении срока хранения не выполняется; срок фиксируется в настройках,
  решение принимает ответственное лицо.
* **Нормативное наполнение** (виды, правила, нормы СИЗ, утверждённые формы) не поставляется — см. [REGULATORY.md](REGULATORY.md).
  Шаблоны печатных форм — примеры, помечаемые как непроверенные.
* **Электронная подпись** не реализована; подтверждения фиксируются как факт (подпись в журнале, скан, иное) с приложением файлов.
* Импорт СИЗ/норм выполняется целиком (при наличии ошибок файл не загружается); импорт сотрудников — построчно с отчётом.
* Полная сборка Docker-образов в среде разработки проверена с ограничением: пакеты Alpine (`openssl`, `postgresql16-client`,
  `tini`) недоступны в песочнице, поэтому образ backend проверен без них (кнопка резервной копии в интерфейсе внутри
  контейнера требует `pg_dump` — в штатной сборке он устанавливается). Сервис `backup` и скрипты работают независимо.

## Рекомендуемые следующие шаги
1. Подключить SMTP-канал (реализация `NotificationChannel`) и корпоративный мессенджер.
2. Интеграция с кадровой системой (регулярная синхронизация вместо ручного импорта).
3. Обучение по программам и тестирование знаний онлайн; электронная подпись.
4. Расширенная аналитика (динамика по периодам, графики) и регламентные выгрузки.
